# Feature Specification: 隐私计算任务算法选择

**Feature Branch**: `004-algorithm-selection`
**Created**: 2026-02-28
**Status**: Draft
**Input**: 为隐私计算任务增加算法选择的功能，包含算法配置管理和任务算法编排两部分

## Clarifications

### Session 2026-02-28

- Q: 算法包文件的最大允许大小是多少？ → A: 200MB，支持包含依赖的大型算法包
- Q: 算法ID应采用什么格式生成？ → A: 使用算法英文名称+版本号作为唯一标识（如 `SPDZ-v1.0`）
- Q: 算法是否需要支持状态生命周期？ → A: 本项目为纯前端实现，状态管理由后端负责，前端仅需调用Mock API
- Q: 前端是否需要对上传的算法包进行基本验证？ → A: 前端不负责后端逻辑实现，所有验证（文件大小、格式等）均由Mock API处理，前端仅调用API并处理返回结果
- Q: 算法管理界面应采用什么导航方式？ → A: 独立页面，入口为Header右侧"设置"下拉菜单，点击后路由跳转到算法管理页面
- Q: 算法类型是否需要区分技术路径（软件/TEE）？ → A: 是，MPC、TEE_MPC、PIR、TEE_PIR等是不同的算法类型，需要区分
- Q: 算法配置在导出JSON中的位置？ → A: 算法配置从属于task，每个隐私计算任务都有自己的算法配置（algorithmId、algorithmParams），作为任务对象的字段
- Q: 如何判断两个算法的参数模板是否"相同"？ → A: 每个算法有独立的参数模板（可能为空），切换算法时始终清空已填写的参数值，无需比较模板是否相同
- Q: 算法包文件在前端如何处理？ → A: Mock场景下算法包上传功能暂不实现，仅保留UI入口（文件上传按钮），Mock数据中算法包字段为空或占位值
- Q: Mock数据应该预置多少条算法？ → A: 为每种算法类型（PSI/TEE_PSI/PIR/TEE_PIR/MPC/TEE_MPC/FL/TEE_FL）各预置1-2条算法，共约10-15条，确保每种任务类型都有可用算法进行测试

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 任务节点自动匹配默认算法 (Priority: P1)

作为隐私计算流程编排人员，当我拖拽一个计算任务节点（如MPC计算）到画布时，系统应该自动为我选择一个最适合的算法（如最新注册的SPDZ协议算法），无需我手动干预。如果该算法定义了附加参数，我可以在节点详情面板中看到这些参数并填写值。

**Why this priority**: 这是核心用户价值 - 简化用户操作，让用户无需关心算法细节即可开始编排任务。这是"开箱即用"体验的基础。

**Independent Test**: 可以通过拖拽一个MPC任务节点到画布，验证系统是否自动选择了创建时间最新的MPC类型算法，并在节点详情中正确显示算法信息来独立测试。

**Acceptance Scenarios**:

1. **Given** 系统中存在多个MPC类型的算法，**When** 用户拖拽一个MPC计算任务节点到画布，**Then** 系统自动为该节点分配创建时间最新的MPC类型算法
2. **Given** 被选中的算法定义了附加参数模板，**When** 用户查看任务节点详情，**Then** 节点详情面板显示算法名称和附加参数输入表单
3. **Given** 被选中的算法没有定义附加参数，**When** 用户查看任务节点详情，**Then** 节点详情面板仅显示算法名称，不显示参数表单
4. **Given** 某任务类型没有任何可用算法，**When** 用户拖拽该类型任务节点，**Then** 系统显示"暂无可用算法"提示，节点仍可创建但算法字段为空

---

### User Story 2 - 手动选择和更换算法 (Priority: P1)

作为隐私计算流程编排人员，当我对系统自动选择的算法不满意时，我可以在任务节点详情面板中手动选择其他可用算法。选择新算法后，如果新算法有不同的参数模板，表单应该自动更新。

**Why this priority**: 这是用户定制化需求的核心 - 让有经验的用户能够根据具体场景选择最适合的算法。与P1-1共同构成完整的任务算法编排体验。

**Independent Test**: 可以通过点击任务节点的算法选择下拉框，验证是否正确显示该任务类型的所有可用算法，选择不同算法后参数表单是否正确更新来独立测试。

**Acceptance Scenarios**:

1. **Given** 任务节点已分配算法A，**When** 用户点击算法选择控件，**Then** 显示该任务类型的所有可用算法列表（包含算法名称、版本号）
2. **Given** 用户正在选择算法，**When** 算法列表展示，**Then** 列表仅显示与当前任务类型匹配的算法（如MPC任务仅显示MPC类型算法，TEE_MPC任务仅显示TEE_MPC类型算法）
3. **Given** 用户选择了新算法B，**When** 选择确认，**Then** 附加参数表单根据新算法的参数模板重新生成，之前填写的值被清空

---

### User Story 3 - 录入和保存附加参数 (Priority: P2)

作为隐私计算流程编排人员，当所选算法定义了附加参数时，我需要填写这些参数值。系统应该根据参数类型（文本、数字、枚举等）提供合适的输入控件，并在导出JSON时将这些参数值包含在任务配置中。

**Why this priority**: 参数配置是算法选择功能的必要补充，让用户能够完整配置算法执行所需的全部参数。

**Independent Test**: 可以通过选择一个带有附加参数的算法，填写参数值，导出JSON并验证参数值是否正确保存来独立测试。

**Acceptance Scenarios**:

1. **Given** 算法定义了字符串类型参数"服务器地址"，**When** 用户查看参数表单，**Then** 显示文本输入框，支持输入和验证
2. **Given** 算法定义了枚举类型参数"加密模式"（选项：AES/SM4），**When** 用户查看参数表单，**Then** 显示下拉选择框，仅允许选择预定义选项
3. **Given** 算法定义了数字类型参数"迭代次数"（最小值1，最大值1000），**When** 用户输入超出范围的值，**Then** 显示验证错误提示
4. **Given** 用户已填写附加参数值，**When** 用户导出流程JSON，**Then** 导出的JSON中包含所选算法ID和填写的参数值

---

### User Story 4 - 查看和管理算法列表 (Priority: P2)

作为系统管理员，我需要查看当前系统中注册的所有算法，可以根据算法类型和名称进行筛选查询。我可以删除不再使用的算法。

**Why this priority**: 算法管理是算法配置功能的基础设施，为任务编排提供算法数据源。

**Independent Test**: 可以通过进入算法管理界面，验证算法列表是否正确显示，筛选和删除功能是否正常工作来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户在流程编辑器界面，**When** 用户点击"算法管理"按钮，**Then** 进入算法管理界面，显示所有已注册算法的列表
2. **Given** 算法列表界面，**When** 用户选择算法类型过滤条件为"MPC"，**Then** 列表仅显示MPC类型的算法
3. **Given** 算法列表界面，**When** 用户在搜索框输入算法名称关键字，**Then** 列表实时过滤显示匹配的算法
4. **Given** 某算法未被任何任务使用，**When** 用户点击删除按钮并确认，**Then** 算法从列表中移除
5. **Given** 某算法已被任务节点使用，**When** 用户尝试删除，**Then** 系统显示警告提示，告知该算法正在被使用

---

### User Story 5 - 注册新算法 (Priority: P2)

作为系统管理员，我需要向系统注册新的算法。我需要提供算法名称、版本号、算法类型、算法包文件，以及可选的参数模板定义。系统会自动记录算法的创建时间。

**Why this priority**: 注册新算法是算法管理的核心功能，让系统能够支持更多算法选择。

**Independent Test**: 可以通过点击"注册新算法"按钮，填写表单并提交，验证新算法是否成功添加到列表中来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户在算法管理界面，**When** 用户点击"注册新算法"按钮，**Then** 显示算法注册表单
2. **Given** 用户正在填写算法注册表单，**When** 用户填写算法名称、版本号、选择算法类型、上传算法包，**Then** 所有必填字段验证通过后，提交按钮变为可用
3. **Given** 用户提交算法注册表单，**When** 注册成功，**Then** 系统自动生成当前时间戳作为创建时间，算法出现在列表中
4. **Given** 用户定义了算法参数模板，**When** 用户完成参数字段配置并提交，**Then** 参数模板以结构化格式保存，可在任务编排时使用

---

### User Story 6 - 定义算法参数模板 (Priority: P3)

作为系统管理员，在注册算法时，我可以通过可视化界面定义该算法的附加参数模板。我可以添加多个参数字段，为每个字段指定名称、类型、验证规则等信息。

**Why this priority**: 参数模板编辑器提升用户体验，让非技术用户也能轻松定义复杂的参数结构。

**Independent Test**: 可以通过在算法注册表单中添加参数字段，配置各种类型和约束，验证模板是否正确保存和渲染来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户在算法注册表单中，**When** 用户点击"添加参数"按钮，**Then** 显示参数配置表单，包含参数名称、类型、是否必填等选项
2. **Given** 用户正在配置参数类型，**When** 用户选择参数类型，**Then** 根据类型显示相应的验证配置选项（如数字类型显示最小/最大值，枚举类型显示选项编辑器）
3. **Given** 用户已添加多个参数，**When** 用户查看参数列表，**Then** 参数以列表形式展示，支持拖拽排序、编辑和删除
4. **Given** 用户完成参数模板定义，**When** 用户保存算法，**Then** 参数模板转换为结构化格式存储

---

### Edge Cases

- 当算法服务不可用时，任务编排界面应如何处理？系统应显示友好的错误提示，任务节点仍可创建但算法选择功能暂时不可用
- 当用户点击算法包上传按钮时，系统显示"Mock模式下暂不支持文件上传"提示（算法包上传功能预留，Mock场景不实现）
- 当用户删除正在被使用的算法时，已使用该算法的任务节点应如何处理？系统应保留已使用算法的快照信息，不影响已配置的任务
- 当算法参数模板包含循环依赖或无效定义时，系统应如何处理？系统应在保存时验证模板结构，拒绝无效的模板定义
- 当用户导出包含算法配置的流程JSON，然后在另一个环境中导入时，目标环境没有对应算法，应如何处理？系统应显示缺失算法的警告，允许导入但标记算法配置为"算法缺失"状态

## Requirements *(mandatory)*

### Functional Requirements

#### 算法配置管理

- **FR-001**: 系统必须提供"算法管理"入口，位于Header右侧"设置"下拉菜单中，点击后路由跳转到独立的算法管理页面
- **FR-002**: 系统必须展示所有已注册算法的列表，包含算法名称、版本号、类型、创建时间等信息
- **FR-003**: 用户必须能够根据算法类型（下拉选择）和算法名称（关键字搜索）筛选算法列表
- **FR-004**: 用户必须能够删除算法，系统应检查算法是否被任务使用并给出相应提示
- **FR-005**: 系统必须提供"注册新算法"功能，允许用户填写算法名称、版本号、算法类型；算法包上传功能在Mock场景下暂不实现，仅保留UI入口
- **FR-006**: 系统必须在算法注册成功时自动记录当前时间戳作为创建时间
- **FR-007**: 系统必须支持为算法定义参数模板，包含参数名称、类型、验证规则等信息
- **FR-008**: 参数模板必须支持多种参数类型：字符串、整数、浮点数、布尔值、枚举、日期、JSON对象、数组
- **FR-009**: 参数模板必须支持验证规则：必填、最小/最大长度、最小/最大值、正则表达式、枚举选项
- **FR-010**: 系统必须提供可视化的参数模板编辑器，支持添加、编辑、删除、排序参数字段

#### 任务算法编排

- **FR-011**: 当用户拖拽计算任务节点到画布时，系统必须根据任务类型自动匹配可用算法
- **FR-012**: 自动匹配算法时，系统必须选择与任务类型匹配且创建时间最新的算法作为默认算法
- **FR-013**: 如果某任务类型没有可用算法，系统必须显示提示信息，节点仍可创建但算法字段为空
- **FR-014**: 任务节点详情面板必须显示当前选中的算法名称和版本号
- **FR-015**: 用户必须能够从任务节点详情面板手动选择/更换算法，算法列表仅显示与任务类型匹配的算法
- **FR-016**: 当算法包含参数模板时，任务节点详情面板必须根据模板动态生成参数输入表单
- **FR-017**: 参数表单必须根据参数类型渲染相应的输入控件（文本框、数字输入、下拉选择、开关等）
- **FR-018**: 参数表单必须根据验证规则进行实时验证，显示验证错误提示
- **FR-019**: 更换算法时，系统必须清空已填写的参数值，根据新算法的参数模板重新生成表单
- **FR-020**: 用户填写的参数值必须在导出JSON时包含在任务配置中
- **FR-021**: 导出的JSON中，每个task必须包含算法配置字段（algorithmId、algorithmName、algorithmVersion、algorithmParams），作为任务对象的属性

#### Mock服务

- **FR-022**: 系统必须提供算法管理的Mock后端服务，支持算法的增删改查操作
- **FR-023**: Mock服务必须提供根据任务类型（computeType）查询匹配算法的接口
- **FR-024**: Mock服务必须提供获取默认算法的接口（指定任务类型下创建时间最新的算法）
- **FR-025**: Mock服务必须预置初始化数据，为每种算法类型（PSI/TEE_PSI/PIR/TEE_PIR/MPC/TEE_MPC/FL/TEE_FL）各提供1-2条算法记录，共约10-15条

### Key Entities

- **算法 (Algorithm)**: 代表一个可执行的计算算法，包含唯一标识符（格式：英文名称-版本号，如 `SPDZ-v1.0`）、名称、版本号、类型（PSI/TEE_PSI/PIR/TEE_PIR/MPC/TEE_MPC/FL/TEE_FL等，区分技术路径）、算法包文件、参数模板、创建时间。每种算法类型可以有多个算法版本。

- **算法参数模板 (AlgorithmParameterTemplate)**: 描述算法执行时需要的附加参数结构，包含参数名称、显示名称、类型、是否必填、验证规则、默认值、描述。一个算法可以有零到多个参数模板项。

- **参数验证规则 (ValidationRule)**: 定义参数值的约束条件，包含规则类型（必填/长度/范围/正则/枚举）和规则参数（如最小长度、最大值、枚举选项列表）。

- **任务算法配置 (TaskAlgorithmConfig)**: 任务节点中保存的算法配置信息，包含选中的算法ID、算法名称、版本号、用户填写的参数值。每个计算任务节点有一个算法配置。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户拖拽任务节点后，系统在1秒内完成默认算法的自动匹配和显示
- **SC-002**: 算法管理界面加载时间不超过2秒，支持展示至少100条算法记录
- **SC-003**: 参数表单根据模板动态生成，用户可在30秒内完成单个算法的参数配置
- **SC-004**: 95%的用户在首次使用时能够成功完成任务节点的算法配置（包含默认匹配或手动选择）
- **SC-005**: 导出的JSON文件100%包含正确的算法配置信息，可通过导入功能完整恢复
- **SC-006**: 参数验证覆盖所有定义的验证规则类型，错误提示在用户输入后即时显示（延迟不超过500ms）
- **SC-007**: 算法注册流程在用户填写完整信息后，5秒内完成注册并更新列表

## Assumptions

1. **纯前端项目**: 本项目为纯前端实现，不负责后端服务开发。所有后端API需提供Mock实现以便测试
2. **算法类型与任务类型对应关系**: 算法类型区分技术路径，包含：PSI、TEE_PSI、PIR、TEE_PIR、MPC、TEE_MPC、FL、TEE_FL等，与任务节点的computeType一一对应
3. **算法包文件处理**: Mock场景下算法包上传功能暂不实现，仅保留UI入口（文件上传按钮），Mock数据中算法包字段为空或占位值
4. **算法ID格式**: 算法唯一标识符采用"英文名称-版本号"格式（如 `SPDZ-v1.0`）
5. **权限控制**: 假设所有用户都能访问算法管理功能，实际部署时可能需要根据角色权限控制
6. **数据持久化**: 算法配置数据使用内存存储+JSON导出的方式，与现有项目架构保持一致
7. **参数模板复杂度**: 参数模板支持常见的表单类型，复杂的嵌套结构通过JSON类型参数支持
8. **算法版本管理**: 暂不支持同一算法名称的版本历史管理，每个算法记录独立存在
