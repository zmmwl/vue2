# Feature Specification: 隐匿查询功能完善与联邦学习任务上线

**Feature Branch**: `003-pir-fl-enhancement`
**Created**: 2026-02-20
**Status**: Draft
**Input**: User description: "隐匿查询功能完善与联邦学习任务上线 - 包括PIR实时数据源支持和联邦学习训练/推断任务"

## Clarifications

### Session 2026-02-20

- Q: 已部署模型的来源是什么？ → A: 从后端API动态获取。已部署模型是曾经与其他参与方一起训练的模型（已有明确的数据参与方），一旦选定，推断的参与方也就确定了（推断的参与方须与训练参与方一致）。
- Q: 当实时数据源没有配置任何字段时，系统如何处理？ → A: 阻止保存/继续，提示用户必须配置至少一个字段。
- Q: 联邦学习菜单的拖拽交互流程是什么？ → A: 先悬停"联邦学习训练"展开四个类型，再悬停某一类型展开具体任务（如逻辑回归、SecureBoost），然后拖拽具体任务到画布，才弹窗配置参数。
- Q: 联邦学习任务的参数配置来源是什么？ → A: 通过API获取参数模板。需要为每种任务创建足够精细的参数配置模板。
- Q: 当用户尝试将PIR输出连接到非PIR任务时，系统如何响应？ → A: 禁止连接，提示"PIR输出只能连接到PIR任务"。
- Q: 当联邦学习任务没有足够的数据源参与方时，系统如何提示？ → A: 在节点配置阶段校验，参与方不足时显示警告，不允许保存。
- Q: 当已部署模型被删除后，依赖该模型的推断任务如何处理？ → A: 打开推断任务详情时提示"模型已被删除"，允许重新选择模型。
- Q: 手工录入的字段类型与实际上传数据不匹配如何处理？ → A: 本平台只负责流程编排，不处理实际传入数据。手工录入的字段信息是定义未来传入数据的元数据结构，实际数据验证由后端执行阶段负责。此边界情况不适用于本平台范围。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 配置隐匿查询实时数据源 (Priority: P1)

隐私计算平台用户需要为隐匿查询(PIR)任务配置实时数据源。与预加载数据源不同，实时数据源的字段信息可以在运行时动态获取或手工录入。用户可以拖拽PIR任务到画布后，配置一个预加载数据源和一个实时数据源作为输入。

**Why this priority**: PIR是核心计算任务之一，实时数据源支持是其与PSI/MPC的关键区别，直接影响业务场景的覆盖范围。

**Independent Test**: 可以通过拖拽PIR任务节点、配置两种数据源、验证实时数据源字段配置流程来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户已拖拽PIR任务节点到画布, **When** 用户配置输入数据源, **Then** 系统允许配置一个预加载数据源和一个实时数据源
2. **Given** 用户正在配置实时数据源, **When** 用户选择"连线导入"方式, **Then** 系统支持从上游节点的输出字段中导入字段信息
3. **Given** 用户正在配置实时数据源, **When** 用户选择"手工录入"方式, **Then** 系统提供字段名称、类型等信息的录入表单
4. **Given** 实时数据源字段已配置, **When** 用户查看PIR节点详情, **Then** 系统区分展示预加载数据源和实时数据源

---

### User Story 2 - 隐匿查询输出作为实时数据源链式调用 (Priority: P1)

用户需要将一个PIR任务的输出结果作为另一个PIR任务的实时数据源输入，实现链式隐匿查询。PIR任务的输出数据节点在界面上应与实时数据源的图形展示一致。

**Why this priority**: 链式PIR是常见业务场景，输出节点的可复用性决定了编排流程的灵活性。

**Independent Test**: 可以通过创建两个PIR任务、将第一个PIR的输出连接到第二个PIR的实时数据源输入来独立测试。

**Acceptance Scenarios**:

1. **Given** 画布上有一个已完成的PIR任务, **When** 用户查看其输出数据节点, **Then** 输出节点以实时数据源的图形样式展示
2. **Given** 画布上有两个PIR任务节点, **When** 用户将第一个PIR的输出连线到第二个PIR, **Then** 第二个PIR识别该输入为实时数据源
3. **Given** 第二个PIR接收了第一个PIR的输出作为实时数据源, **When** 用户配置字段映射, **Then** 系统自动加载上游输出的字段信息

### User Story 3 - 联邦学习训练任务 - 预处理 (Priority: P2)

用户需要使用联邦学习预处理任务对本地数据进行清洗和格式化。预处理是本地任务，只能接入一个数据源，且不产生额外的输出数据节点。

**Why this priority**: 预处理是联邦学习流程的第一步，为后续特征工程和模型训练准备数据。

**Independent Test**: 可以通过拖拽"预处理"任务、选择一个数据源、配置处理参数来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户在左侧菜单悬停"联邦学习训练", **When** 展开任务类型列表, **Then** 显示"预处理"选项
2. **Given** 用户选择"预处理"类型, **When** 展开具体任务列表, **Then** 显示可用的预处理任务（数据清洗、格式转换等）
3. **Given** 用户拖拽预处理任务到画布, **When** 配置任务参数, **Then** 系统弹窗显示可配置参数并支持填写
4. **Given** 预处理任务已配置完成, **When** 用户查看节点详情, **Then** 系统显示完整配置信息并支持重新编辑
5. **Given** 预处理任务只有一个输入数据源, **When** 用户尝试连接第二个数据源, **Then** 系统提示预处理只支持单个数据源

### Edge Cases

- 当实时数据源没有配置任何字段时，系统阻止保存/继续，提示用户必须配置至少一个字段。
- 当用户尝试将PIR输出连接到非PIR任务时，系统禁止连接，提示"PIR输出只能连接到PIR任务"。
- 当联邦学习任务没有足够的数据源参与方时，系统在节点配置阶段校验，参与方不足时显示警告，不允许保存。
- 当已部署模型被删除后，打开推断任务详情时系统提示"模型已被删除"，允许重新选择模型。

### Interaction Specifications (交互规范)

#### 数据源切换行为

- 当用户在实时数据源配置中从"连线导入"切换到"手工录入"时，系统必须清空已有字段信息，避免数据来源混淆。
- 切换时必须显示确认提示："切换将清空当前字段配置，是否继续？"

#### 弹窗取消行为

- 当用户在参数配置弹窗中点击"取消"或"关闭"时，系统必须放弃当前节点创建，不生成任何节点。
- 如果是编辑已有节点，取消后恢复该节点到编辑前的状态。

#### 参数重新编辑

- 双击已配置的任务节点，必须重新打开参数配置弹窗，显示当前保存的参数值。
- 修改参数后点击"确认"，必须更新节点显示的配置摘要。

#### 参数配置弹窗布局规范

- 弹窗宽度：固定 560px（移动端响应式除外）
- 参数标签宽度：120px，右对齐
- 输入区域宽度：剩余空间，最小 200px
- 参数间距：16px
- 分组标题：14px 加粗，上下间距 24px

#### 实时数据源字段类型校验规则

- 字段名称：仅允许字母、数字、下划线，首字符必须为字母或下划线
- 字段类型：必须从预定义类型列表中选择（STRING, INTEGER, FLOAT, BOOLEAN, DATE, TIMESTAMP）
- 字段描述：可选，支持中英文及常见标点

#### 配置完成判定标准

- **PIR任务配置完成**：已配置预加载数据源 或 已配置实时数据源（至少1个字段）
- **FL任务配置完成**：所有必填参数已填写且通过验证
- **参数配置正常**：所有必填字段已填写，数值参数在有效范围内，无校验错误

### Success Criteria Measurement Methods (验收标准测量方法)

- **SC-001 测量方法**：从打开PIR任务配置弹窗到点击"确认"关闭弹窗的时间，使用前端埋点记录
- **SC-002 验证方法**：自动化测试验证任意两个PIR任务可以建立输出-输入连接
- **SC-004 测量方法**：从拖拽FL任务到画布到点击配置弹窗"确认"的时间，使用前端埋点记录
- **SC-007 测量方法**：用户测试，记录无指导情况下完成完整流程的成功率（样本量≥20）

## Requirements *(mandatory)*

### Functional Requirements

#### 隐匿查询(PIR)相关

- **FR-001**: 系统必须支持PIR任务配置两种数据源类型：预加载数据源和实时数据源
- **FR-002**: 系统必须限制PIR任务只能接受一个预加载数据源和一个实时数据源作为输入
- **FR-003**: 系统必须支持实时数据源通过连线方式从上游节点导入字段信息
- **FR-004**: 系统必须支持实时数据源通过手工录入方式配置字段信息（字段名、类型、描述）
- **FR-005**: 系统必须将PIR任务的输出数据节点以实时数据源的图形样式展示
- **FR-006**: 系统必须支持PIR输出作为下游PIR任务的实时数据源输入
- **FR-007**: 系统必须在节点详情中区分展示预加载数据源和实时数据源信息

#### 联邦学习菜单相关

- **FR-008**: 系统必须将左侧菜单"联邦学习"改名为"联邦学习训练"
- **FR-009**: 系统必须在悬停"联邦学习训练"时展开四个任务类型：预处理、特征工程、横向模型、纵向模型
- **FR-010**: 系统必须在鼠标移动到任务类型时展开该类型下的可选任务列表
- **FR-010-1**: 用户必须选择并拖拽具体任务（如逻辑回归、SecureBoost）到画布，拖入后才弹窗配置参数
- **FR-011**: 系统必须新增左侧菜单"联邦学习推断"选项
- **FR-012**: 系统必须在悬停"联邦学习推断"时展开四个任务类型：预处理、特征工程、横向模型、纵向模型

#### 联邦学习预处理任务

- **FR-013**: 系统必须支持预处理任务只能接入一个数据源
- **FR-014**: 系统必须确保预处理任务不产生额外的输出数据节点
- **FR-015**: 系统必须提供预处理任务的参数配置弹窗，包括数据清洗、格式转换等参数
- **FR-016**: 系统必须支持预处理任务的详情展示和重新编辑

#### 联邦学习特征工程任务

- **FR-017**: 系统必须支持特征工程任务接入多参与方的多个数据源
- **FR-018**: 系统必须为特征工程任务生成输出数据节点
- **FR-019**: 系统必须提供特征工程任务的参数配置弹窗，包括样本对齐、特征选择、特征交叉等参数
- **FR-020**: 系统必须支持特征工程任务的详情展示和重新编辑

#### 联邦学习模型任务

- **FR-021**: 系统必须支持横向模型任务类型，包括逻辑回归、XGBoost、CNN、RNN、Transformer等
- **FR-022**: 系统必须支持纵向模型任务类型，包括SS-LR、SecureBoost、FM、拆分学习等
- **FR-023**: 系统必须为每种模型提供对应的参数配置项
- **FR-023-1**: 系统必须从后端API动态获取每种任务的参数配置模板
- **FR-024**: 系统必须支持模型任务的详情展示和重新编辑
- **FR-025**: 系统必须为模型任务生成输出数据节点

#### 联邦学习推断任务

- **FR-026**: 系统必须从后端API动态获取已部署模型列表
- **FR-029**: 系统必须在用户选择已部署模型后，自动确定推断参与方（与训练参与方一致）
- **FR-027**: 系统必须提供推断任务的参数配置弹窗
- **FR-028**: 系统必须支持推断任务的详情展示和重新编辑

### Key Entities

- **实时数据源(RealtimeDataSource)**: 一种新的数据源类型，字段可动态配置，区别于预加载数据源
  - 字段来源：连线导入或手工录入
  - 字段信息：名称、类型、描述

- **隐匿查询任务(PIRTask)**: 特殊的计算任务，支持双数据源输入
  - 预加载数据源：来自数据资产
  - 实时数据源：来自连线或手工配置
  - 输出：实时数据源类型

- **联邦学习任务(FLTask)**: 联邦学习相关任务
  - 任务类别：训练(Training) / 推断(Inference)
  - 任务类型：预处理 / 特征工程 / 横向模型 / 纵向模型
  - 具体任务：根据类型确定

- **联邦学习预处理任务(FLPreprocessTask)**: 本地单方任务
  - 输入：单个数据源
  - 输出：无额外输出节点（原地处理）

- **联邦学习特征工程任务(FLFeatureEngineeringTask)**: 多方协同任务
  - 输入：多参与方的多个数据源
  - 输出：输出数据节点

- **联邦学习模型(FLModel)**: 横向/纵向模型配置
  - 模型类型：具体算法
  - 训练参数：模型特定的参数配置
  - 推断参数：用于推断时的配置

- **已部署模型(DeployedModel)**: 可用于推断的模型
  - 模型ID、名称、版本
  - 训练参与方列表：曾参与训练的参与方信息
  - 推断约束：推断任务的参与方必须与训练参与方一致

### FL Task Parameter Templates

联邦学习各任务的参数配置模板，通过后端API动态获取。

#### 预处理任务参数

| 任务名称 | 参数名 | 参数类型 | 必填 | 说明 |
|---------|--------|---------|------|------|
| **数据清洗** |
| | missingValueStrategy | select | 是 | 缺失值处理策略：删除/均值填充/中位数填充/常数填充 |
| | fillConstant | number | 否 | 常数填充值（当策略为常数填充时） |
| | outlierMethod | select | 否 | 异常值处理方法：不处理/删除/替换为边界值 |
| | outlierThreshold | number | 否 | 异常值阈值（如3σ） |
| **格式转换** |
| | dateFormat | text | 否 | 日期格式转换目标格式（如YYYY-MM-DD） |
| | encodingMethod | select | 否 | 类别编码方式：LabelEncoding/OneHot |
| **ID标准化** |
| | idFormat | select | 是 | ID格式：手机号11位/身份证18位/自定义 |

#### 特征工程任务参数

| 任务名称 | 参数名 | 参数类型 | 必填 | 说明 |
|---------|--------|---------|------|------|
| **样本对齐(PSI)** |
| | hashAlgorithm | select | 是 | 哈希算法：SHA256/MD5/SM3 |
| | saltEnabled | boolean | 否 | 是否启用加盐 |
| | saltValue | text | 否 | 盐值（加盐时） |
| **特征选择** |
| | selectionMethod | select | 是 | 选择方法：IV值/相关系数/模型重要性 |

## Non-Functional Requirements

### Visual Design Requirements (视觉设计)

#### 节点视觉标识

- **NFR-VD-001**: 实时数据源节点必须使用虚线边框（dashed border）与预加载数据源节点的实线边框区分
- **NFR-VD-002**: PIR输出节点必须使用与实时数据源相同的视觉样式（虚线边框 + 浅蓝色背景 #E6F7FF）
- **NFR-VD-003**: 联邦学习任务节点必须按类别使用不同颜色标识：
  - 预处理任务: #52C41A (绿色)
  - 特征工程任务: #1890FF (蓝色)
  - 横向模型任务: #722ED1 (紫色)
  - 纵向模型任务: #FA8C16 (橙色)
- **NFR-VD-004**: 联邦学习任务节点必须显示模式徽章：
  - 训练模式: 显示 "训练" 标签（蓝色背景）
  - 推断模式: 显示 "推断" 标签（绿色背景）

#### 交互视觉反馈

- **NFR-VD-005**: 三级菜单悬停展开延迟必须为 150ms，过渡动画时长 200ms (ease-out)
- **NFR-VD-006**: 拖拽任务到画布时，目标位置必须显示虚线占位框
- **NFR-VD-007**: 连接验证失败时，连线必须显示为红色虚线（#FF4D4F）
- **NFR-VD-008**: 参数保存成功/失败必须通过 Toast 消息提示（成功绿色，失败红色）

### API Error Handling (API错误处理)

- **NFR-API-001**: 获取已部署模型列表失败时，必须显示友好错误提示："无法获取已部署模型列表，请稍后重试"，并提供"重试"按钮
- **NFR-API-002**: 获取参数模板失败时，必须显示友好错误提示："无法加载参数配置模板"，并阻止节点创建
- **NFR-API-003**: API请求超时时间必须设置为 10 秒，超时后自动重试 1 次
- **NFR-API-004**: 已部署模型列表为空时，必须显示空状态提示："暂无已部署模型，请先完成模型训练"

### Accessibility Requirements (无障碍访问)

- **NFR-A11Y-001**: 三级菜单必须支持键盘导航：Tab 键在菜单项间切换，Enter 键展开/选择
- **NFR-A11Y-002**: 参数配置弹窗打开时，焦点必须自动移至第一个可输入字段
- **NFR-A11Y-003**: 参数配置弹窗必须支持 Esc 键关闭
- **NFR-A11Y-004**: 所有错误提示必须包含 aria-live="polite" 属性以支持屏幕阅读器
- **NFR-A11Y-005**: 交互元素（按钮、菜单项）必须有明确的 aria-label

### Responsive Design (响应式设计)

- **NFR-RWD-001**: 参数配置弹窗在屏幕宽度 < 768px 时，必须调整为全宽显示
- **NFR-RWD-002**: 侧边栏菜单在屏幕宽度 < 576px 时，必须自动折叠为图标模式
- **NFR-RWD-003**: 节点详情面板在窄屏下必须从右侧滑入而非固定显示

### Edge Case Specifications (边界条件)

#### 实时数据源

- **NFR-EC-001**: 实时数据源字段数量下限为 1，上限为 50
- **NFR-EC-002**: 字段名称长度限制为 1-64 个字符
- **NFR-EC-003**: 字段描述长度限制为 0-256 个字符

#### 联邦学习任务

- **NFR-EC-004**: 特征工程任务最小参与方数量为 2，最大为 10
- **NFR-EC-005**: 模型训练任务最小参与方数量为 2，最大为 10
- **NFR-EC-006**: PIR链式调用最大嵌套层级为 5 层

#### 参数范围约束

- **NFR-EC-007**: learningRate 参数范围: 0.0001 - 1.0
- **NFR-EC-008**: iterations/epochs 参数范围: 1 - 10000
- **NFR-EC-009**: numTrees 参数范围: 1 - 1000
- **NFR-EC-010**: maxDepth 参数范围: 1 - 32

### Performance Requirements (性能要求)

- **NFR-PERF-001**: 三级菜单展开响应时间 < 100ms
- **NFR-PERF-002**: 参数配置弹窗打开时间 < 200ms
- **NFR-PERF-003**: 节点拖拽渲染帧率 ≥ 30fps
- **NFR-PERF-004**: 画布支持至少 100 个节点无性能下降

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在30秒内完成PIR实时数据源的字段配置（手工录入或连线导入）
- **SC-002**: 100%的PIR任务支持链式调用，即一个PIR的输出可作为另一个PIR的输入
- **SC-003**: 联邦学习菜单支持4种任务类型的二级展开，每种类型至少显示3个可选任务
- **SC-004**: 用户可在1分钟内完成任意联邦学习任务的基础参数配置
- **SC-005**: 所有联邦学习任务节点支持详情查看和参数重新编辑
- **SC-006**: 推断任务支持从已部署模型列表中选择，列表加载时间不超过2秒
- **SC-007**: 95%的用户能够独立完成从拖拽联邦学习任务到配置完成的完整流程
