这是一个非常关键的问题，准确地划分这两者，是设计联邦学习方案的基础。

简单来说，划分的核心原则是：**任何需要全局统计信息（如全局均值、全局方差、全局特征重要性）的操作，都必须通过隐私保护的方式协同完成；而只需要依赖本地数据分布的操作，则可以在本地独立完成。**

下面我将为你系统地梳理和区分这两类操作。

### 第一类：可在本地独立完成的预处理与特征工程

这类操作主要处理的是数据格式、单个样本的清洗以及基于本地数据分布的转换。由于不涉及跨方的信息聚合，因此不需要复杂的加密协议，各参与方可以独立、并行地执行。

- **数据清洗**
    - **格式统一与ID标准化**：各方在自己的系统中，将用户ID、时间戳等字段统一成相同的格式（如将手机号统一为不带国家码的11位数字），为后续的样本对齐做准备。
    - **缺失值处理**：
        - **删除**：删除本地数据中缺失率过高的列或行。
        - **填充**：使用本地的均值、中位数、众数或常数（如0）进行填充。**注意**：如果希望使用全局均值填充，则需要进入第二类协同操作。
    - **异常值检测与处理**：基于本地的3σ原则或四分位距（IQR）法则，识别并剔除或修正本地数据中的异常值。
    - **数据类型转换**：将日期字符串转换为时间戳，将类别字符串转换为整数代码（Label Encoding），前提是各方独立维护自己的映射表。

- **基础特征构造**
    - **单字段特征提取**：从单个字段中提取信息。例如，从身份证号中提取出生日期、性别、地域代码；从时间戳中提取“是/不是周末”、“是/不是节假日”等特征。
    - **简单的数学变换**：对特征取对数、平方、开根号等，这些操作仅依赖字段自身的值。

- **数据划分**
    - **训练/测试集分割**：各方在本地，利用随机数种子将自己的数据集划分为训练集和测试集。为了保证全局评估的准确性，需要确保各方使用的随机数种子是一致的，但这通常由协调方在下发任务时指定，数据本身仍在本地操作。

### 第二类：必须各方协同、采用隐私保护方式做的预处理与特征工程

这类操作的核心是需要利用各方数据的全局统计特性，或者需要在各方之间建立关联。如果直接暴露原始数据或中间统计量，可能会造成隐私泄露，因此必须依赖密码学或分布式算法来完成。

- **样本对齐**
    - **PSI（隐私保护集合交集）**：这是纵向联邦学习的起点。各方在不泄露己方全部用户ID的前提下，找出多方共有的用户。必须使用**不经意传输、哈希加盐**或**Diffie-Hellman密钥交换**等密码学技术来实现。如果只是简单地把ID哈希后发出去，容易遭受彩虹表攻击，是不安全的。

- **联合统计量计算**
    - **全局归一化/标准化**：如果需要将数据统一到全局均值和全局方差下进行标准化，就需要在保护各参与方本地统计量（和、平方和、计数）的前提下，计算全局的均值和标准差。通常采用**同态加密**或**安全聚合**协议来实现。
    - **全局分位数计算**：在进行特征分箱时，如果想基于全局数据分布来确定分箱的边界（例如，基于全局的等频分箱），就需要通过**联邦分位数算法**来近似计算全局的分位数，而不能直接合并所有数据。例如，Google的DP算法和FATE中的分位数计算模块。

- **联邦特征选择**
    - **基于相关性的特征选择**：在纵向联邦中，如果需要计算Guest方（拥有标签的一方）的特征与Host方（只拥有特征的一方）的特征之间的皮尔逊相关系数，或者计算IV值（信息价值），必须通过加密方式（如**同态加密**）来计算协方差等中间结果，防止直接暴露特征值和标签值。
    - **基于模型的特征重要性评估**：在训练基于树的模型（如SecureBoost）过程中，模型会计算每个特征在分裂节点时的贡献度（增益）。这个过程本身就是联邦的，各方的特征重要性是在不泄露原始数据的情况下，通过加密梯度信息来间接评估的。

- **联邦特征交叉**
    - **隐私保护的组合特征生成**：如果需要构造来自不同参与方的特征之间的交叉项（例如，A方的“年龄”乘以B方的“收入”），传统的明文乘法已不可行。这时需要利用**同态加密**技术：一方将特征加密后发给另一方，另一方在密文上进行乘法运算，然后将结果返回，由原始方解密得到交叉特征。整个过程保证了双方的原始数据都不泄露。

### 总结对比

为了更直观地展示，我整理了一个表格：

| 操作类别 | 具体操作项 | 能否本地独立做？ | 若需协同，原因及关键技术 |
| :--- | :--- | :--- | :--- |
| **数据清洗** | 格式统一、ID标准化 | **是** | 仅涉及本地字符串/格式处理。 |
| | 缺失值填充 | **是 (用本地均值)** | 若用**全局均值**填充，则需协同计算全局均值（需同态加密）。 |
| | 异常值剔除 | **是 (基于本地分布)** | 若需基于全局分布判断异常值，则需协同（需联邦分位数算法）。 |
| **基础特征构造** | 单字段特征提取 | **是** | 例如从身份证提取出生地、年龄，仅依赖本地的字符串解析。 |
| **数据划分** | 训练/测试集分割 | **是** | 各方独立划分，但需约定相同的随机种子以保证标签分布一致。 |
| **样本对齐** | 找出共有用户ID | **否** | 必须通过**PSI（隐私保护集合交集）** 协议，防止ID泄露。 |
| **联合统计量** | 全局归一化/标准化 | **否** | 计算全局均值/方差需聚合各方统计量，必须用**安全聚合**。 |
| | 全局分箱边界确定 | **否** | 计算全局分位数需用**联邦分位数算法**，不能直接合并数据。 |
| **联邦特征选择** | 计算跨方特征相关性 | **否** | 计算协方差涉及Guest标签与Host特征，需用**同态加密**。 |
| **联邦特征交叉** | 生成跨方组合特征 | **否** | 涉及多方原始数据的乘法运算，必须用**同态加密**。 |
